# Original delivery and assessor applicability

Six blind assessments tested a prospective procedure against synthetic delivered objects.
Each case retains the exact prompt, original stop receipt, report products, friction, source-file hashes and independent review.
The source base and candidate patch identity are in [record.json](record.json).

A, B and C contain the same scientific answer in committed, uncommitted/ignored and later coordinator-preserved deliveries.
All three recognized the answer; B and C did not award passing worker-tracking credit for the seed or later preservation.
This supports the original-delivery boundary, not equality of all checklist judgments.

D exposed a repeated ambiguity: an ordinary NumPy dependency was treated as a separately maintained project module.
The prospective fix places the component boundary beside the item and in its probe hint.
E correctly marks that item's empty subject not applicable; F still detects a copied independent component with missing upstream identity.
D's unsuccessful judgment remains unchanged.
Incomplete-environment judgments still vary and require the planned duplicate assessments; these fixtures do not establish universal assessor reliability.

The complete archive, including object Git histories, exact skill snapshots, native sessions and all failed and successful validation logs, belongs to the [iteration subdataset](https://github.com/leej3/stamped-in-practice/tree/codex/iteration-narps-v1/skill-reflection/assessment-neutrality-trial-01).
No scientific workflow was replayed, no NARPS result was regraded, and no efficacy claim follows from this development check.
