# Compare skill conditions

Use only for an explicit evaluation of skills or agent conditions.

Before either arm: freeze task/data/rubric, skill revision and complete tree, model/runtime, limits, permitted tools/access, assistance and allocation.
Use fresh contexts and separate writable workspaces.
Materialize the intended skill version; distinguish checked-out files from shared host configuration and external paths.
Both arms receive equivalent scientific resources; expose treatment guidance only where assigned.
Separate available resources and coordinator preservation from worker requirements.
Do not impose the treatment’s tools or practices on a baseline unless that constrained workflow is explicitly the estimand.

Predeclare separate scientific and research-object criteria.
Fix expected values independently; the treatment output is not the baseline's answer key.
Hide arm labels during assessment where feasible, and identify deterministic, self-assessed, independent-agent and human evidence separately.

Keep every attempted outcome, including timeout/interruption, before any assisted repair. Record deviations, intervention timing, retries and reasons for exclusions. Report setup, worker, evaluation and packaging costs separately; give measurement units/scope and leave unavailable usage unknown.
A skill read is exposure, not proof of application or effectiveness.

Environmental changes may be part of the task; record what each arm actually used and apply the same declared policy.
A changed common task, delivery requirement or assessor defines a new comparison setup; do not attribute a difference across that boundary solely to skills.
Test revised guidance on new workers, retain earlier outcomes, and freeze common measurement before comparing skill revisions.
Repeated matched trials and varied execution order are needed for broader inference; one small pair cannot establish general efficacy or credit an individual instruction.
