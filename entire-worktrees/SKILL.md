Use the project's prepared launcher when available.
Keep host credentials and tool locations outside tracked files; reuse existing providers.
Prepare each writable checkout before launching a fresh agent: pinned submodules, its own environment, annex delivery route, native Entire configuration and composed Git hooks.

For a project shipping `scripts/prepare_launch.py`, the coordinator supplies a branch, task prompt, evidence directory and declared condition.
Host defaults supply the installed CLI, approval source, resolver and remote endpoints.
Preserve preparation receipts with the owning experiment.
Missing ordinary project packages belong in its manifest; do not substitute another project's environment.

Native hook approval is path-specific.
Reuse trust only for byte-identical already-approved hooks; preserve explicit denials and require review of changed hooks.
Compose capture, formatting and provenance hooks without replacing or double-wrapping them.
Clear inherited session IDs before a new native CLI session.

Worktrees isolate tracked files, not host instructions or credentials.
Where isolated conditions matter, use a clean host profile and inspect the effective loaded instructions.
Keep common resource guidance identical between arms.
Installed runtime behavior can differ from documentation: verify that skill exclusions actually take effect.

A configuration receipt is not capture evidence.
Exercise a real file change and normal attributed commit; verify the stored native transcript, checkpoint, session identity and intended checkout.
Test branch switches, new worktrees, clones and delegated children separately.
A child may retain its parent's session directory even when its commands use another checkout; inspect actual paths and commit linkage.

Publish exact intended code and checkpoint refs, compare remote object IDs, then verify authenticated hosted identity.
Obtain dashboard links from the actual UI.
Automatic publication is a separate project choice; keep it disabled during setup trials.
Report API verification and UI availability separately, and limit coverage claims to the tested launch route.
